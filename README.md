# Portfolio

Source of my portfolio: case studies of the mapping tools I build, with a short German profile page.
It is a small static site generated by one Python script. No framework, no database, no cookies, no third-party requests.

Live site: https://florentchevallier.github.io/portfolio/

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate      # optional
pip install -r requirements.txt
python build.py --serve                                 # http://localhost:8000, rebuilds when you save a file
```

`python build.py` builds once into `dist/`. `python build.py --strict` also fails on any warning
(broken link, missing image); this is what the GitHub Action runs.

## How it is organised

```
content/
  site.yml                  name, role, public URL, e-mail, links, home-page pitch
  data/profile.yml          skills, experience, education, languages (English and German in one place)
  data/de.yml               texts of the German page
  pages/about.md            text of the About page
  projects/<slug>/index.md  one folder per project: front matter + Markdown + its images
templates/                  Jinja2 layout (base, home, project, about, German page)
static/                     CSS, JavaScript, self-hosted fonts, favicon, social image
tools/                      new_project.py (skeleton), make_contours.py (hero artwork, run rarely)
build.py                    the generator
.github/workflows/pages.yml builds and deploys on every push to main
```

## Add a project

```bash
python tools/new_project.py "Name of the project"
```

This creates `content/projects/name-of-the-project/index.md` with every option explained in comments and
`draft: true`, so it appears locally but not online. Put images next to `index.md`, write the story, remove
the `draft` line, commit, push.

The front matter controls how the project appears:

| Field | Effect |
|---|---|
| `title`, `kind`, `status`, `year` | Card and page header. `kind` is free text: Web map, Python tool, Static map... |
| `summary`, `summary_de`, `lead` | Card text, German card text, longer introduction under the title |
| `order`, `featured` | Position on the home page; `featured: false` lists it on `/projects/` only |
| `tags` | Technologies shown on the card |
| `cover`, `cover_alt`, `cover_ratio` | Image in the project folder, its description, its width / height |
| `links` | Buttons. `primary: true` styles one; `card: true` also shows it on the home page card |
| `facts` | Label / value pairs in the panel beside the text |
| `embed` | Interactive embed (an iframe) loaded only when the visitor presses the button |
| `draft: true` | Hidden from the published site |

A project needs only `title`, `summary`, `kind` and `order`. Without a cover, facts or embed the page is
still laid out properly, which suits a simple static map or a code snippet.

Inside the Markdown: `##` headings become the "On this page" list, tables and fenced code blocks work,
and figures are plain HTML:

```html
<figure>
  <img src="my-figure.svg" alt="What the figure shows" loading="lazy">
  <figcaption>One sentence of context.</figcaption>
</figure>
```

## Languages

Case studies are English only. The German page (`/de/`) gives a profile and links to them. To keep it cheap:

- Skills, experience, education and languages live once in `content/data/profile.yml`, with `en:` and `de:` values.
- Each project may add `kind_de`, `status_de`, `summary_de` and `label_de` on its links; without them the English text is used.
- Texts specific to the German page are in `content/data/de.yml`.

## Deploy on GitHub Pages

1. Push this repository to GitHub.
2. Settings, then Pages, then Build and deployment: set Source to **GitHub Actions**.
3. Every push to `main` builds and publishes the site.

All links are relative, so the site works under `/portfolio/`, at `<user>.github.io`, or on a custom domain.
If the address changes, update `url` in `content/site.yml` (used for canonical links, the sitemap and social previews).

## Before publishing

- Read every sentence in the case studies and the About page: they are written in my voice and must be right.
- Check `content/data/profile.yml` against the current CV (dates, wording).
- Do not commit a CV containing a home address or phone number.
- If you add a LinkedIn address, uncomment `linkedin` in `content/site.yml`.
- Restrict any map-provider API key used in an embedded project to your domains in the provider's dashboard.

## Design notes

- Palette and type are CSS variables at the top of `static/css/site.css`. Light and dark themes follow the visitor's system.
- Fonts: Overpass (headings, interface) and Vollkorn (reading text), self-hosted, SIL Open Font License; licences are in `static/fonts/`.
- The hero contours are synthetic terrain generated by `tools/make_contours.py`. Run it with another `--seed` for a new landscape;
  the result is committed, so the build does not need numpy.
- The contour reveal on the home page respects `prefers-reduced-motion`.
